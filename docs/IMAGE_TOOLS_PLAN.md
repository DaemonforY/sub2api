# 图片处理工具箱（设计稿，未开发）

起因：用户在画布「参考图改图」一次传了几张大照片，请求超过上游 20MB 上限连续失败，却没有地方压缩图片。现在发送前会自动压缩（`fitReferenceFiles`），但用户仍然缺少一个能主动处理图片的地方。

## 1. 现状：能力不少，但入口藏得深

画布（canvas.hivegpt.cn）已经有的：

| 能力 | 位置 | 实现 |
|---|---|---|
| 裁剪、旋转、翻转、调色（亮度/对比度/饱和度/色温/锐化/暗角…）、8 个滤镜 | 图片编辑器弹窗（画布图片节点、生图工作台结果图） | 浏览器本地 |
| 局部编辑（蒙版涂抹后重绘） | 画布图片节点 | 调用改图模型 |
| 切图（按行列切分，九宫格） | 画布图片节点 | 本地 |
| 放大到 1K/2K/4K | 画布图片节点 | 本地插值（不是 AI） |
| 多角度、反推提示词 | 画布图片节点 | 调用模型 |
| AI 超分 | 画布工具栏有按钮 | **未实现** |
| 发送前自动压缩参考图 | 改图请求 | 本地，刚上线 |

问题：
1. 这些工具只在「已经放进画布 / 已经生成出来的图」上能用，**上传参考图的那一刻**（最需要压缩、裁剪的时候）用不了。
2. 没有独立入口，不进画布就找不到；也不支持批量。
3. 缺少几个常见刚需：压缩 / 转格式 / 改尺寸、抠图去背景、扩图、AI 超分、加文字水印、拼图。

## 2. 方案：一套「图片工具」能力，三个入口

**入口 A：上传时就地处理（优先做）**
参考图上传后，缩略图上显示大小；超过阈值标红「图片较大，已自动压缩 / 点击处理」。点开即是图片编辑器，多一个「压缩与尺寸」页签。画布的参考图栏、生图工作台、视频工作台共用。

**入口 B：独立工具箱页面 `canvas.hivegpt.cn/tools`**
顶部导航加「图片工具」。拖入一张或多张图 → 选工具 → 预览 → 下载 / 存入素材库 / 发到画布。

**入口 C：画布节点工具栏**
现有工具栏补上新工具（抠图、扩图、超分），复用同一套实现。

## 3. 工具清单与实现方式

原则：**能在浏览器本地做的都本地做**（免费、不上传、不占服务器）；需要模型的走本站网关，按次计费，复用现有的计费和错误提示。

| 工具 | 说明 | 实现 | 收费 |
|---|---|---|---|
| 压缩 | 目标大小或质量滑块，显示前后大小对比 | 本地 Canvas 重编码（WebP/JPEG），复用 `fitReferenceFiles` | 免费 |
| 转格式 | PNG / JPEG / WebP 互转，HEIC（iPhone 照片）转 JPEG | 本地；HEIC 需引入 heic 解码库（按需加载） | 免费 |
| 改尺寸 | 按长边 / 百分比 / 常用尺寸（1:1、3:4、16:9、小红书、公众号封面） | 本地 | 免费 |
| 裁剪、旋转、调色、滤镜 | 已有，挪进统一编辑器 | 本地 | 免费 |
| 加文字 / 水印 | 文字、字号、颜色、位置、透明度，可批量 | 本地 | 免费 |
| 拼图 / 切图 | 多图拼长图、宫格拼图；已有切图 | 本地 | 免费 |
| 批量处理 | 多张图同一套操作（压缩 / 改尺寸 / 转格式 / 加水印），打包 zip 下载 | 本地，Web Worker 防卡顿 | 免费 |
| 抠图 / 去背景 | 输出透明 PNG，可换纯色 / 模糊背景 | 方案一：调用改图模型（简单，效果一般、贵）；方案二：服务端部署开源抠图模型（rembg/BiRefNet，CPU 一张约 1–3 秒，效果好、成本低） | 按次 |
| AI 超分 | 2×/4× 清晰化（补上已有按钮） | 服务端 Real-ESRGAN 类模型，或接第三方超分接口 | 按次 |
| 扩图 | 选择方向和比例向外延展画面 | 改图模型 + 自动生成蒙版（复用局部编辑的流程） | 按改图计费 |
| 局部重绘 / 消除物体 | 已有蒙版编辑，增加「消除」快捷模式（不用写提示词） | 改图模型 | 按改图计费 |
| 反推提示词 | 已有，放进工具箱 | 视觉模型 | 按 token |

不做：去除他人水印 / Logo（版权风险），换脸 / 真人换装（上游安全系统也会拒）。

## 4. 技术要点

- **统一编辑器内核**：把现有 `image-editor-dialog` + `lib/image-editor/*` 抽成「操作流水线」（crop → resize → adjust → text → encode），预览和导出走同一套代码；批量就是把同一条流水线跑在多张图上。
- **大图性能**：用 `createImageBitmap` + `OffscreenCanvas` 放进 Web Worker；超过 8000px 的图先降采样预览，导出时再全尺寸处理；浏览器内存不够时给出明确提示。
- **服务端 AI 工具**（抠图、超分）：
  - 在 sub2api 网关里加一个「图片工具」平台，`POST /v1/images/tools/{remove-bg|upscale}`，用户的 API Key 鉴权、按次计费、失败不扣费，统一中英文错误提示。
  - 推理服务单独一个容器（Python + onnxruntime，CPU 版），只在内网暴露给网关；当前服务器 4 核 7GB 可以先跑 CPU 版，量大了再换 GPU 或第三方接口。
  - 不额外存储用户图片：处理完直接返回，结果由用户决定是否存入素材库。
- **与上传限制联动**：上游单次 20MB 的限制写进前端常量；任何会发给上游的图片都在发送前过一遍压缩（已上线），工具箱里的「压缩」也默认以这个限制为目标。

## 4.1 抠图 / 超分接口调研（2026-10-01）

结论：没有适合商用网站长期免费使用的接口；最省钱、最可控的是**自建开源模型**，云厂商接口作为付费兜底。

| 方案 | 抠图 | 超分 | 说明 |
|---|---|---|---|
| mxnzp（ROLL API） | 无 | 无 | 只有文生图、二维码、节假日等工具接口；个人项目，无 SLA |
| alapi / apihz / aa1 / uomg 等聚合站 | 无 | 无 | 只有压缩等基础工具 |
| 天行 API 人像抠图 | 仅人像，免费 30 次 | — | 之后约 ¥0.015–0.02/次 |
| 百度智能云 | 人像分割：总共免费 1 万次（企业 5 万次），1 年有效；通用抠图 ¥0.03/次 | 无损放大（仅 2 倍）：免费 1000 次，之后 ¥0.006/次 | 需实名；条款禁止转售接口，作为本站功能使用可以 |
| 阿里云视觉智能 | 通用抠图 ¥0.002/次，无免费额度 | 超分 1–4 倍：每月免费 100 次，之后 ¥0.02/次 | 需实名；平台在逐步收缩能力 |
| 腾讯云数据万象 | 通用抠图 ¥0.02/次 | 超分 2 倍 ¥0.006、4 倍 ¥0.009；新用户一次性各 1000 次 | 需 COS 存储桶，首尔不在支持地域，要用新加坡/香港 |
| remove.bg | 每月 50 次且只有预览分辨率 | — | 自助 API 2026-12-01 关闭，不考虑 |
| **自建 rembg（isnet-general-use 模型）** | 免费，MIT/Apache 许可可商用；4 核 CPU 约 1–3 秒/张 | — | 注意 rembg 默认模型 RMBG-2.0 **商用要付费授权**，必须显式指定 isnet / birefnet-lite |
| **自建 Real-ESRGAN（realesr-general-x4v3）** | — | 免费，BSD 许可；CPU 上 1024px 输入 4 倍约 10–40 秒 | 需要排队异步处理，输入限制 1024px |

建议：P3 先自建 rembg（isnet）+ Real-ESRGAN x4v3，跑在首尔服务器单独容器里排队处理，上线前先在服务器上实测速度；量大或要更好效果时，抠图接阿里云（¥0.002/次）、超分接腾讯云数据万象或百度。

## 4.2 首尔服务器实测（2026-10-01，Xeon 8255C，容器限 3 核 / 4GB）

| 模型 | 用途 | 每张耗时 | 内存 | 结论 |
|---|---|---|---|---|
| rembg u2net | 抠图 | 0.5–0.7 秒（与原图大小基本无关，模型内部固定 320px） | < 1GB | 快，边缘粗，可做「快速模式」 |
| rembg isnet-general-use | 抠图 | 1.2–1.9 秒（内部固定 1024px） | 约 1–1.5GB | **推荐**：单主体人像、商品效果可用，复杂背景 / 多主体拼图效果一般 |
| rembg birefnet-general-lite | 抠图 | — | 4GB、5.5GB 限制下都被 OOM 杀掉 | 这台服务器跑不了 |
| Real-ESRGAN x4v3（onnxruntime，256px 分块） | 4 倍超分 | 512px→2048px 2.4–3.2 秒；768px→3072px 5–7 秒；1024px→4096px 8–11 秒 | < 1GB | **推荐**：文字、边缘明显变清晰，人脸会偏平滑 |

模型加载约 15 秒，服务要常驻、预热；同一时间只处理 1 个任务，其余排队。

## 6. 需要你决定的事

1. 工具箱放在画布站（建议，和生图流程在一起）还是主站也要有入口。
2. 抠图 / 超分是自建推理容器（便宜，占服务器 CPU）还是接第三方接口（省事，按量付费）。
3. AI 工具的单价（建议抠图、超分按次计费，价格低于一次生图）。
