# 教程 / 文章分享卡片（第一期已开发）

目标：在 `/learn` 的教程和文章页上，让读者一键生成一张适合发朋友圈 / 微信群 / 小红书的图片，图片里带内容和一个扫码直达全文的二维码，二维码带上分享者的邀请码。

两种卡片：

| | 摘录卡（选中段落） | 概要卡（点「分享」） |
|---|---|---|
| 触发 | 正文里选中一段文字 → 浮出「生成卡片」 | 页面标题旁 / 文末的「分享」按钮 |
| 内容 | 选中的原文 + 出处（页面标题） | 标题 + 一句话简介 + 3–4 条要点 + 阅读时长 |
| 二维码 | 跳到全文，并滚动到选中段落所在的小节 | 跳到全文开头 |

## 1. 范围

- **`/learn`（VitePress）**：全部 290 篇 md（教程路线、guide 文章、connect 接入教程、codex、bigdata）都自动获得这个功能，不需要逐篇改。
- **主站课程详情页 `/courses/:slug`**：概要卡（标题、副标题、章节名当要点、课时数和创作者），课程介绍 / 试看 / 常见问题里选中文字可生成摘录卡。
- **主站模型广场 `/models`（独立形态）**：概要卡（模型总数、按平台的模型数和示例模型名）。
- 不做：公众号编辑器里的文章（发出去后在微信里，不在本站）。
- 首页、路线索引页这类没有正文的页面（frontmatter `layout: home` / `share: false`）不显示。

## 2. 交互

### 2.1 摘录卡

1. 在正文 `.vp-doc` 内选中文字，松开鼠标（手机上是选区稳定 300ms 后）出现一个小工具条：`生成卡片 · 复制`。
   - 电脑：工具条浮在选区上方。
   - 手机：系统自带的选区菜单会挡住上方，改为固定在屏幕底部的一条横栏。
2. 只在正文里生效：AI 助教、RunBox 运行框、测验、模拟面试这些组件里选中文字不弹出。
3. 字数：少于 6 个字不弹出；超过 300 字仍可生成，但卡片里截到 300 字加「…」，并提示「已截取前 300 字」。
4. 选中跨了代码块 / 表格时用 `selection.toString()` 的纯文本；代码行在卡片里用等宽字体、浅灰底，保留换行；图片和公式忽略。
5. 点「生成卡片」→ 打开卡片弹窗（见 2.3）。

### 2.2 概要卡

- 「分享」按钮放两处：`LessonHeader`（标题下方，和阅读时长同一行）和 `LessonFooter`（文末，旁边写「觉得有用？分享给朋友」）。
- 点了直接生成概要卡，打开同一个弹窗。

### 2.3 卡片弹窗

- 上面是卡片预览（就是最终的 PNG），下面四个风格可切换：**蜂巢紫**（默认）/ **蜂蜜橙** / **青碧** / **墨夜**，选过的风格记在浏览器里。
- 操作：
  - 手机（含微信内置浏览器）：提示「长按图片保存或发送给朋友」。微信内置浏览器不支持下载，长按图片是唯一可靠的方式。
  - 电脑：`下载图片`、`复制图片`（`ClipboardItem`，不支持时隐藏）、`复制链接`。
  - 支持 `navigator.share({ files })` 的手机浏览器，多一个「分享到…」按钮。
- 没登录：卡片照样能生成，底部多一行小字「登录后生成的二维码带你的邀请码，好友注册你得返利」+ 登录链接（`loginUrl()` 会带回本页）。

## 3. 卡片内容与版式

画布宽 1080px，高度随内容变化，最小 1350（4:5），最大 1920（9:16），超出就截断原文。

**朋友圈辨识度**：朋友圈背景有白色和深色两种，所以卡片不用白底或黑底，而是一圈饱和的渐变色边框，上面铺一层淡淡的蜂巢六边形纹理（HiveGPT 的「蜂巢」），中间是一张圆角纸片卡承载内容，右下角有一个蜂蜜色六边形作为标志。缩略图（多图时被裁成正方形）里也能一眼看出是同一系列。四套配色：

| 风格 | 边框渐变 | 纸片 |
|---|---|---|
| 蜂巢紫（默认） | #4c1d95 → #7c3aed → #c026d3 | 白 |
| 蜂蜜橙 | #f59e0b → #f97316 → #e11d48 | 米白 |
| 青碧 | #0f766e → #0891b2 → #2563eb | 白 |
| 墨夜 | #0b1023 → #1e1b4b → #3b0764，琥珀色蜂巢 | 深蓝 |

```
┌──────────────────────────────┐
│ HiveGPT AI 学习   · 路线名       │  品牌 + 所属路线 / 栏目（tracks.ts）
│                                │
│  “                             │
│   选中的原文……（摘录卡）          │  44px 正文，行高 1.7
│   或：标题 + 简介 + 要点（概要卡）  │
│                                │
│  —— 《页面标题》                │
│ ─────────────────────────────  │
│ [二维码]  扫码阅读全文             │  二维码 220px
│           分享者昵称 推荐 · 3 分钟读完 │
│           来源 JavaGuide · Apache-2.0 │  仅转载文章
└──────────────────────────────┘
```

### 3.1 概要卡的「关键文字」从哪来

不调用大模型：生成要快（< 300ms）、零成本、内容稳定可控。按优先级取：

1. frontmatter 里手写的 `share`（可选，给重点文章用）：
   ```yaml
   share:
     points: ["Agent = 模型 + 工具 + 循环", "MCP 解决的是工具接入的标准化", "……"]
     quote: "一句适合放在卡片中间的金句"
   ```
2. 没写就自动生成：`description` 当一句话简介，前 4 个二级标题（`##`）当要点，标题过长时截到 22 个字。
3. 阅读时长按正文字数估算（400 字/分钟）。

这些在**构建时**算好：在 `config.mts` 里加 `transformPageData`，把 `shareCard = { title, track, summary, points, minutes, source }` 写进页面数据。浏览器端只读 `useData().page.value.shareCard`，不用在运行时扒 DOM。

### 3.2 转载文章的署名

38 篇 guide 文章转载自 JavaGuide（Apache-2.0）。卡片上必须带「来源 JavaGuide · Apache-2.0」。构建时检测 frontmatter 的 canonical 指向 `javaguide.cn` 就标为转载。
注意：二维码链接用本站地址，**不能用 canonical**（canonical 指向原站）。

## 4. 二维码链接

```
https://hivegpt.cn/learn/<path>.html?aff=<邀请码>&utm_source=share_card&utm_medium=quote#<小节锚点>
```

- `aff`：登录用户的邀请码，从主站 `/api/v1/user/aff` 取（同源，learn 已经有 token），拿一次缓存到 sessionStorage。`theme/index.ts` 里的 `rememberAffiliate()` 已经会记住 `?aff=`，好友扫码后在 learn 注册也能绑定邀请人，这条链路已经通了。
- `utm_medium`：`quote` / `summary`，埋点归因里能区分是哪种卡片带来的访问。
- 锚点：摘录卡取选区之前最近的 `h2/h3` 的 id；不用 `#:~:text=`，因为微信和 Safari 旧版不支持。
- 链接尽量短，保证二维码的码点不会太密（纠错级别 M，220px 在手机上扫起来稳）。

## 5. 实现

纯前端，后端不改，不存任何东西。

| 文件 | 作用 |
|---|---|
| `learn/.vitepress/theme/shareCard.ts` | 绘图：`drawQuoteCard(opts)` / `drawSummaryCard(opts)` → PNG dataURL。Canvas 2D 手动排版（中文逐字测宽换行、英文按单词换行、标点避头尾），三套配色。从 `poster.ts` 抽出公用的字体、二维码、圆角卡片函数。 |
| `components/SelectionShare.vue` | 监听 `.vp-doc` 的选区，显示浮动 / 底部工具条。挂在 `Layout.vue` 的 `layout-bottom` 插槽。 |
| `components/ShareCardDialog.vue` | 弹窗：预览、切换风格、保存 / 复制 / 分享。 |
| `components/ShareButton.vue` | 「分享」按钮，放进 `LessonHeader` / `LessonFooter`。 |
| `config.mts` | `transformPageData` 生成 `shareCard` 数据（见 3.1）。 |

为什么用 Canvas 手绘，不用 html2canvas / html-to-image：
- 证书海报已经这么做，`qrcode` 依赖已经在，不加新依赖。
- html2canvas 在微信内置浏览器里字体、渐变、跨域图片经常出问题，输出也不稳定。
- 卡片版式固定，手绘排版的代码量不大（约 250 行）。

细节：
- 画之前 `await document.fonts.ready`；字体用系统字体栈（和 `poster.ts` 的 `FONT` 一样），不加载网络字体。
- 同一页、同一段文字、同一风格的结果缓存起来，切换风格时只重画。
- 不做 SSR：组件都在 `onMounted` 之后才工作。

## 6. 埋点

用现有的 `track()`：

| 事件 | 属性 |
|---|---|
| `share_card_open` | `kind`（quote/summary）、`theme`、`chars` |
| `share_card_save` | `kind`、`method`（download/copy/share/longpress_hint） |
| `share_link_copy` | `kind` |

回流用页面浏览的 `utm_source=share_card` 归因看：分享 → 打开 → 注册 → 首充。在后台数据看板加一个「分享卡片」漏斗（第二期）。

## 7. 验收

- 电脑 Chrome / Safari、iPhone Safari、安卓 Chrome、**微信内置浏览器（iOS + 安卓）** 都能生成、能长按保存。
- 中英文混排、长英文单词 / URL、代码块、只有一个字的选区、跨两个小节的选区，排版不溢出。
- 二维码用微信扫一扫能打开并滚动到对应小节；登录时链接带 `aff`，未登录时不带。
- 转载文章的卡片有来源署名。
- vitest 覆盖：换行算法（中文 / 英文 / 标点避头尾 / 截断）、链接拼接、`shareCard` 数据提取。
