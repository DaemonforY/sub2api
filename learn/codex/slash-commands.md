# 斜杠命令

在 Codex CLI 的输入框里打一个 `/`，会弹出命令列表。这些命令不发给模型，而是直接控制会话本身：换模型、改权限、审阅改动、压缩上下文、管理 MCP 工具等等。用熟它们，比在对话里反复解释「请帮我换一种方式」高效得多。

这一页按官方仓库 `codex-rs/tui/src/slash_command.rs` 整理全部命令，先给分组总表，再把最常用的几个展开讲。

::: tip 以你本机为准
Codex 更新很快，命令会增删。输入 `/` 后弹出的列表就是你当前版本真正可用的命令；有些命令要打开对应功能开关或在特定系统上才会出现（下文会注明）。
:::

## 先知道几个输入技巧

斜杠命令之外，输入框还认几个前缀，经常和命令配合用：

| 输入 | 作用 |
|---|---|
| `/` | 打开命令列表，继续输入可过滤，例如 `/re` 会筛出 `/review`、`/resume`、`/rename` |
| `@` | 搜索并插入项目里的文件路径，让模型直接读这个文件 |
| `$` | 提及一个 Skill 或工具，例如 `$pdf`，让 Codex 按这个 Skill 的方法做事 |
| `!` | 把后面的内容当 shell 命令直接执行，例如 `!git status`，结果会进入对话上下文 |

命令名不区分先后，前缀匹配即可；回车执行。带参数的命令可以直接把参数写在后面，例如 `/review 只看安全问题`。

## 全部命令一览

### 会话管理

| 命令 | 作用 | 什么时候用 |
|---|---|---|
| `/new` | 在当前进程里开一个新会话 | 换一个不相关的任务，不想让旧上下文干扰 |
| `/clear` | 清空终端并开新会话 | 和 `/new` 类似，顺便把屏幕也清干净 |
| `/resume` | 从历史里挑一个会话接着聊 | 昨天没做完的任务今天继续 |
| `/fork` | 把当前会话复制一份，从这里分叉 | 想试另一种方案，又不想丢掉现在的进度 |
| `/side`（别名 `/btw`） | 开一个临时的旁支对话 | 插一句和主任务无关的问题，问完回到主线 |
| `/rename` | 给当前会话改名 | 方便以后在 `/resume` 列表里找到 |
| `/archive` | 归档当前会话 | 做完的任务收起来，列表更清爽 |
| `/delete` | 永久删除当前会话记录 | 会话里有不该留存的内容时 |
| `/worktree` | 在新的 Git worktree 里开始或继续会话 | 并行做多个任务，互不踩文件（需功能开启） |
| `/app` | 把当前会话转到桌面应用继续 | 想换到图形界面看 diff（仅 macOS / Windows） |
| `/copy` | 复制上一条回复或其中一部分 | 把回答贴到别处 |
| `/export` | 把对话导出成 Markdown | 留档、写周报、分享给同事 |
| `/raw` | 切换原始滚动模式，便于终端里选中复制 | 终端选中文字不方便时 |
| `/quit`、`/exit` | 退出 Codex | 结束工作 |

### 模型与权限

| 命令 | 作用 | 什么时候用 |
|---|---|---|
| `/model` | 选择模型和推理强度 | 任务变难或变简单时调整，详见 [模型与推理强度](/codex/models) |
| `/permissions` | 选择 Codex 能做什么（只读 / 默认 / 完全访问等） | 临时放宽或收紧权限，详见 [沙箱与审批](/codex/sandbox) |
| `/approve` | 对最近一次被自动审查拒绝的操作，批准重试一次 | 开了自动审查、它拦错了时 |
| `/plan` | 切换到计划模式：先出方案，不动文件 | 大改动前先对齐思路（需协作模式开启） |
| `/goal` | 设置或查看长任务的目标，可 `/goal pause`、`/goal resume`、`/goal clear` | 让 Codex 围绕一个明确目标持续推进（需 goals 功能） |
| `/experimental` | 打开或关闭实验性功能 | 想试新功能时 |
| `/setup-default-sandbox` | 配置提权版的 Windows 沙箱 | 仅 Windows 下出现 |
| `/daybreak` | 开关 Daybreak 模式 | 仅在你的账号和版本提供时出现 |

如果当前模型支持不同服务档位（例如更快的优先档），`/model` 下方还会多出对应的档位命令，名字和说明以列表为准。

### 代码审阅

| 命令 | 作用 | 什么时候用 |
|---|---|---|
| `/review` | 让 Codex 审阅改动、找问题 | 提交前自查、合并前看分支差异 |
| `/diff` | 显示 `git diff`，包括未跟踪的新文件 | 看 Codex 到底改了哪些地方 |

### 上下文与工作目录

| 命令 | 作用 | 什么时候用 |
|---|---|---|
| `/init` | 生成一份 `AGENTS.md`，写入项目说明 | 新项目第一次用 Codex |
| `/compact` | 把对话总结压缩，腾出上下文空间 | 长会话快到上下文上限 |
| `/recap` | 立刻总结一下当前对话 | 离开一会儿回来，快速回忆进度 |
| `/mention` | 插入一个文件引用 | 等同于输入 `@` 选文件 |
| `/status` | 显示当前会话配置和 token 用量 | 确认模型、权限、目录、上下文剩余 |
| `/cd` | 切换当前工作目录 | 任务换到同一仓库的另一个子项目 |
| `/pwd`（别名 `/cwd`） | 显示当前工作目录 | 不确定 Codex 在哪个目录操作时 |
| `/ide` | 带上 IDE 里的当前选区、打开的文件等上下文 | 配合 IDE 扩展使用 |
| `/memories` | 设置记忆的使用和生成 | 想让 Codex 记住或别再记某些偏好 |
| `/usage` | 查看账号用量 | 订阅登录时看额度（视账号类型出现） |

### 工具与扩展

| 命令 | 作用 | 什么时候用 |
|---|---|---|
| `/mcp` | 列出已连接的 MCP 服务和工具；`/mcp verbose` 看详情，`/mcp login 名称` 做 OAuth 登录 | 排查 MCP 工具为什么没出现，详见 [MCP](/codex/mcp) |
| `/skills` | 浏览和启用 Skills | 详见 [Skills](/codex/skills) |
| `/hooks` | 查看和管理生命周期钩子 | 详见 [规则与钩子](/codex/hooks) |
| `/plugins` | 浏览插件 | 安装别人打包好的 Skills / MCP 组合 |
| `/apps` | 管理应用连接 | 连接外部应用（视功能开启） |
| `/agents` | 打开代理指挥中心 | 同时管理多个会话或代理 |
| `/subagents` | 在本会话的子代理之间切换 | 详见 [子代理](/codex/subagents) |
| `/ps` | 列出后台运行的终端 | 看 dev server 之类的长命令还在不在 |
| `/stop`（别名 `/clean`） | 停止所有后台终端 | 后台进程占端口、占资源时 |
| `/import` | 从 Claude Code 导入配置、项目和近期对话 | 从其他编程助手迁移过来 |
| `/voice` | 开始或停止语音，`/voice settings` 选声音 | 想用语音交互（视功能开启） |

| `/statusline` | 配置底部状态栏显示哪些信息 |
| `/title` | 配置终端标题栏显示哪些信息 |
| `/keymap` | 重新映射快捷键 |

| `/pets`（别名 `/pet`） | 选择或隐藏终端宠物 |
| `/warnings` | 查看保留下来的警告和诊断信息 |
| `/debug-config` | 显示各配置层及其来源，排查「配置为什么没生效」 |
| `/daemon` | 管理本地后台服务 |
| `/feedback` | 把日志发给维护者 |
| `/logout` | 退出登录 |

::: details 任务运行中能用哪些命令？
Codex 正在干活时，部分命令会被拒绝，因为它们会改变会话状态。源码里明确**不能**在任务进行中使用的有：`/new`、`/clear`、`/fork`、`/delete`、`/worktree`、`/init`、`/compact`、`/recap`、`/review`、`/plan`、`/cd`、`/export`、`/logout`、`/experimental`、`/memories`、`/import`、`/keymap`、`/vim`、`/tui`、`/theme`、`/pets` 等。

`/model`、`/permissions`、`/diff`、`/status`、`/mcp`、`/copy`、`/side`、`/ps`、`/stop` 这类查看或切换的命令则可以随时用。想改主意时，先按 Esc 打断当前任务，再执行命令。
:::

## 常用命令详解

### /model：换模型和推理强度

```text
/model
```

弹出列表后先选模型，再选推理强度（low、medium、high 等，具体选项取决于模型）。选择从下一轮对话开始生效，并且会作为默认值写回配置文件里的 `model` 和 `model_reasoning_effort`，下次启动仍然沿用。

实用节奏：日常改代码用默认的 `gpt-5.5` + medium；碰到难排查的 bug、跨多个模块的重构，临时调到 high 或 xhigh；做完记得调回来，否则下次启动还是高强度，费时间也费 token。只想临时用一次高强度，用命令行 `codex -c 'model_reasoning_effort="high"'` 更合适，它不会改动配置文件。

### /permissions：调整权限

```text
/permissions
```

列表里有三个内置预设：

| 预设 | 文件 | 命令与网络 | 审批 |
|---|---|---|---|
| Read Only | 只读当前工作区 | 改文件、联网需要你批准 | 按需询问 |
| Default | 可读写当前工作区、运行命令 | 联网或改工作区外文件需要批准 | 按需询问 |
| Full Access | 不受沙箱限制 | 不受限制 | 从不询问 |

Default 是绝大多数时候的正确选择。只有在容器、虚拟机这类本身就隔离的环境里，才考虑 Full Access。完整原理见 [沙箱与审批](/codex/sandbox)。

::: warning 没有 /approvals
很多旧教程写的是 `/approvals`。当前版本统一叫 `/permissions`；而 `/approve` 是另一个命令，只用于批准「自动审查拒绝过的那一次操作」重试，不要混淆。
:::

### /review：提交前让 Codex 先审一遍

```text
/review
```

不带参数时会让你选审阅范围：

1. **对比基础分支**：选一个分支（如 `main`），审阅当前分支相对它的全部改动，适合提 PR 前；
2. **未提交的改动**：暂存、未暂存和未跟踪的文件都算，适合每次 commit 前；
3. **某个提交**：从提交列表里挑一个；
4. **自定义要求**：自己写审阅指令。

也可以直接带上要求，跳过选择：

```text
/review 重点看 SQL 注入和权限校验，忽略代码风格
```

审阅结果会按问题列出文件和行号，Codex 不会自动改代码；你看完再说「修复第 1、3 条」即可。`config.toml` 里的 `review_model` 可以给审阅单独指定模型。命令行里对应的是 `codex review`，见 [命令行参数](/codex/cli-reference)。

### /diff：看清楚改了什么

```text
/diff
```

显示工作区相对 HEAD 的完整 diff，**包括新建的未跟踪文件**，这一点比直接跑 `git diff` 更全。每完成一步就看一眼 diff，是避免「AI 悄悄改了不该改的文件」最简单的办法。

### /compact：长会话续命

```text
/compact
```

Codex 会把到目前为止的对话写成一份摘要，用摘要替换原始历史，腾出上下文空间。默认情况下上下文接近上限时它也会自动压缩，手动压缩的好处是你可以挑时机：比如一个阶段做完、下一阶段开始前。

::: tip 压缩还是新开
如果接下来的任务和之前关系不大，`/new` 比 `/compact` 更干净：摘要难免丢细节，也难免把旧任务的假设带进新任务。
:::

### /new、/resume、/fork：管理多个会话

```text
/new                 开新会话
/resume              打开历史会话列表
/fork                从当前位置复制出一个分支会话
/rename 登录页重构   给当前会话起个好找的名字
```

会话记录保存在 `~/.codex/sessions/` 下，退出后不会丢。命令行里 `codex resume --last` 可以直接接上最近一次会话，`codex fork` 则从历史会话分叉。

`/side`（或 `/btw`）适合插问：主任务正在进行，你突然想问「这个正则什么意思」，开个旁支问完就回来，不会污染主线上下文。

### /init：生成 AGENTS.md

```text
/init
```

Codex 会扫描项目结构、构建脚本和测试命令，生成一份 `AGENTS.md` 草稿。之后每次在这个项目启动，它都会先读这份文件。生成后一定要人工改一遍：删掉猜错的内容，补上「提交前必须跑哪些检查」「哪些目录不要碰」这类只有你知道的规则。写法见 [AGENTS.md](/codex/agents-md)。

### /mention 与 @：精确指定文件

```text
@src/api/user.ts 这个文件里的分页参数校验有问题，帮我看看
```

与其让 Codex 自己搜索，不如直接指明文件，又快又准。`/mention` 的效果和输入 `@` 一样。

### /status：确认当前状态

```text
/status
```

会显示当前模型、推理强度、工作目录、权限设置、账号信息和 token 用量。下面这些情况先跑一下 `/status`：

- 改了 `config.toml` 但不确定生效没有；
- Codex 说没有权限写文件；
- 想知道上下文还剩多少，要不要 `/compact`。

如果要追查某个配置值来自哪一层（用户配置、项目配置还是命令行），用 `/debug-config`。

### /mcp：检查外部工具

```text
/mcp
/mcp verbose
/mcp login github
```

列出已配置的 MCP 服务和它们暴露的工具。配置了却看不到工具，先用 `/mcp verbose` 看启动错误；需要 OAuth 的服务用 `/mcp login 服务名` 完成授权。配置方法见 [MCP](/codex/mcp)。

### /ps 与 /stop：后台进程

让 Codex 启动 dev server、watch 进程时，它们会作为后台终端运行。`/ps` 列出这些进程，`/stop` 一次全部停掉，避免端口被占、电脑风扇狂转。

## 自定义命令：用 Skills 代替

旧版本的 Codex 支持在 `~/.codex/prompts/` 里放 Markdown 文件，变成 `/prompts:文件名` 这样的自定义命令。当前源码里这条路已经移除，弹出列表只包含内置命令。

现在想把常用流程固化下来，用 **Skills**：

```text
~/.agents/skills/commit-msg/SKILL.md
```

```markdown
---
name: commit-msg
description: 根据暂存区改动写一条约定式提交信息
---

1. 运行 git diff --cached 查看暂存的改动。
2. 按 type(scope): subject 的格式写一行标题，不超过 72 个字符。
3. 正文用中文分点说明改了什么、为什么改。
4. 只输出提交信息，不要执行 git commit。
```

在会话里输入 `$commit-msg` 就能调用；即使不显式提及，Codex 也会在任务和 description 匹配时自动使用。比起旧的 prompts，Skills 还能附带脚本和参考文件，放在仓库的 `.agents/skills/` 里还能跟项目一起共享（旧位置 `~/.codex/skills/` 仍然兼容）。详见 [Skills](/codex/skills)。

## 一个推荐的工作节奏

把上面的命令串起来，一次完整的小任务大致是：

```text
/status                         确认模型、权限、目录
/plan 给用户列表加分页          先出方案（或直接描述任务）
……确认方案，让它动手……
/diff                           看改动
/review                         选「未提交的改动」自查
……让它修复审阅意见……
!git add -A && git commit       自己提交
/new                            下一个任务
```

## 小结

- 输入 `/` 看到的列表就是本机可用命令；部分命令依赖功能开关或操作系统。
- 权限切换用 `/permissions`（不是 `/approvals`），模型和推理强度用 `/model`。
- 每一步改完先 `/diff`，提交前 `/review`；长会话用 `/compact`，换任务用 `/new`。
- `@` 指定文件、`$` 调用 Skill、`!` 直接跑 shell 命令。
- 自定义命令请用 Skills，旧的 `~/.codex/prompts` 已不再出现在命令列表里。
