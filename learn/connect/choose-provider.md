# API 中转站怎么选

**看三件事：价格能不能和官方标价对上、每次请求的扣费能不能逐条查到、失败的请求扣不扣钱。** 再加上稳定性、接口支持、数据处理和充值规则，下面 8 项都能自己验证。先充一点小额试用，确认没问题再多充。

> 更新于 2026-10。

## 8 项检查

| # | 看什么 | 怎么验证 |
|---|---|---|
| 1 | **价格怎么算**：按官方美元标价、按倍率，还是自定义价格 | 拿一次请求的 token 数，按官方单价算一遍，和扣费对比 |
| 2 | **计费能不能逐条查**：每次请求的模型、输入 / 输出 / 缓存 token、扣费 | 控制台里有没有按请求的使用记录 |
| 3 | **失败扣不扣钱**：限流、超时、上游报错 | 故意用错误的模型名请求一次，看有没有扣费 |
| 4 | **模型是不是真的**：请求 A 模型，实际给的是不是 A | 看返回里的 `model` 字段；复杂任务对比官方效果；价格明显低于官方标价很多的要警惕 |
| 5 | **稳定性和并发**：高峰期能不能用、有没有并发限制 | 连续用几天；问清楚并发和每分钟请求数的限制 |
| 6 | **接口支持**：Chat Completions、Responses、流式、函数调用、画图、嵌入 | 用你实际要用的工具（Codex、Cherry Studio 等）各试一次 |
| 7 | **数据怎么处理**：是否保存请求内容、保存多久、用来做什么 | 看服务条款和隐私政策，没有写的就问客服 |
| 8 | **充值和退款**：最低充值、有效期、能否退款、能否开票 | 看充值页和服务条款 |

## 自己动手验证

**1. 用 curl 测接口和返回的模型名**

```bash
curl https://你的服务地址/v1/chat/completions \
  -H "Authorization: Bearer sk-你的Key" \
  -H "Content-Type: application/json" \
  -d '{"model": "gpt-5.5", "messages": [{"role": "user", "content": "你是什么模型？"}]}'
```

看返回里的 `model` 和 `usage`。注意：模型自己说「我是 XX」并不可靠，以返回的字段和实际效果为准。

**2. 对一遍账**

找一条使用记录，用它的 token 数按官方单价算一遍：

```text
输入 token × 输入单价 + 输出 token × 输出单价 + 缓存 token × 缓存单价
```

算出来和扣费一致（或按公布的倍率一致），说明计费透明。算法见 [token 怎么算钱](/connect/tokens)。

**3. 试一次失败请求**

把模型名写错发一次，正常的服务会返回明确的报错，而且不扣费。

## 需要警惕的情况

- **价格远低于官方标价**，又说不清楚来源。
- **只能看到余额变化**，看不到每次请求扣了多少。
- **报错只有一句「error」**，看不出是 Key、余额还是上游的问题。
- **要求一次性大额充值**，或充值后不能退。
- **服务条款里没有数据处理的说明**，而你要发送的是工作资料或个人信息。

## 以 HiveGPT 为例

对照上面的检查项，HiveGPT 的做法是：

- 按模型的官方美元标价计费，充值 ¥1 = $1 额度，各模型单价在 [模型广场](https://hivegpt.cn/model-plaza) 公开。
- [使用记录](https://hivegpt.cn/usage) 里能查到每次请求的模型、token 数和扣费。
- 限流、超时、上游报错的请求不扣费，报错会写明原因和处理方法，见 [报错速查](/connect/errors/)。
- 支持 Chat Completions、Responses、流式和画图接口，各工具的接法见 [接入教程](/connect/)。

建议你用同样的方法验证，先小额充值试用。

## 常见问题

**中转和直接用官方有什么区别？** 官方 API 需要在官方支持的地区注册和付款；中转服务提供兼容的接口和国内的付款方式。区别主要在价格、稳定性和服务，按上面的清单比较即可。

**一个 Key 能在多个工具里用吗？** 能。但建议每个工具单独建一个 Key 并设额度上限，花费分得清，泄露时也只影响一个。

**怎么判断是不是被「换了模型」？** 看返回的 `model` 字段，并用你熟悉的复杂任务对比效果；价格低得离谱时要格外小心。
