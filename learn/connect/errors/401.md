# API 报错 401：API Key 无效 / 未授权

**401 说明请求已经到达 HiveGPT，但 Key 没通过验证。** 地址是对的，不用改；按报错提示检查 Key：重新到 [API 密钥](https://hivegpt.cn/keys) 页复制完整的 Key（`sk-` 开头），确认它是「启用」状态，填进工具后重试。

> 更新于 2026-10。

## 按报错内容判断

| 报错（`code`） | 原因 | 处理 |
|---|---|---|
| 「缺少 API Key」（`API_KEY_REQUIRED`） | 请求里根本没带 Key | 在工具的 API Key / API 密钥一栏填上 Key；自己写代码时检查请求头 |
| 「API Key 无效或已被删除」（`INVALID_API_KEY`） | Key 复制不全、多了空格，或这个 Key 已经删除 | 重新复制完整的 Key；删除了就新建一个 |
| 「API Key 已停用」（`API_KEY_DISABLED`） | 你在控制台停用了这个 Key | 到「API 密钥」页启用它，或换一个 Key |
| 「Too many invalid authentication attempts」（`INVALID_AUTH_RATE_LIMITED`，429） | 短时间内用错误的 Key 请求太多次 | 先把 Key 改对，等几分钟再试 |

## 最常见的几种填错

1. **Key 没复制完整。** Key 很长，双击选中时容易少选一段。在「API 密钥」页用复制按钮复制。
2. **前后带了空格或换行。** 从聊天记录、文档里复制时容易带上，粘贴后检查一下首尾。
3. **Key 填到了别的栏。** 例如填进了地址栏，或填进了「组织 ID」一栏。
4. **自己写代码时请求头写错。** 正确的写法是：

   ```
   Authorization: Bearer sk-你的Key
   ```

   `Bearer` 和 Key 之间有一个空格。也支持 `x-api-key: sk-你的Key`。

5. **用了别家的 Key。** OpenAI 官方、其他平台的 Key 不能用在 HiveGPT 上，反过来也一样。

## 用 curl 确认是不是 Key 的问题

```bash
curl https://hivegpt.cn/v1/models \
  -H "Authorization: Bearer sk-你的Key"
```

- 返回模型列表：Key 没问题，检查工具里的配置。
- 返回 401：Key 本身有问题，按上面的表格处理。

## 403：Key 已过期或分组不可用

这几种报错的状态码是 403，同样和 Key 有关：

| 报错（`code`） | 原因 | 处理 |
|---|---|---|
| 「API key 已过期」（`API_KEY_EXPIRED`） | 这个 Key 到了创建时设置的过期时间 | 在「API 密钥」页修改过期时间，或新建一个 Key |
| 「API Key 所属分组已停用」（`GROUP_DISABLED`）或分组已删除（`GROUP_DELETED`） | Key 绑定的分组不再提供 | 新建一个 Key，选一个当前可用的分组 |
| 「API Key 所属专属分组不再允许当前用户使用」（`GROUP_NOT_ALLOWED`） | 专属分组的使用权限被收回 | 换一个公开分组的 Key |

余额不足、订阅无效也是 403，见 [余额不足 / 额度已用完](/connect/errors/quota)。

## Key 泄露了怎么办

立刻到 [API 密钥](https://hivegpt.cn/keys) 页删除它，再新建一个，把新 Key 填进你的工具。删除后旧 Key 马上失效，别人再用会收到 401。

其他报错看 [报错速查](/connect/errors/)。
